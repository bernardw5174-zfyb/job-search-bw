# 国内求职方法论（job-search-bw）

> 一个普通的技术人，把求职做成了一门**可以公开检验**的学科。
> 这不是鸡汤，是投递记录、实验日志和假设注册表堆出来的**方法与它的当前状态**。

## 这是什么

国内求职的四环方法包：**诊断 → 关键词 → 改写 → 模拟面试**。

**我们卖的是验证机制，不是结论**：每条主张都标状态与证据强度——
✅ 部分成立的写部分成立，不成立的写不成立，未验证的标待验证。

> 本包方法务实为先，**不追求统计显著**；证据以个人样本为主，属方向性信号。

## 兼容性

兼容遵循 AGENTS.md／SKILL.md 约定的 Agent。

**实测记录建立中**——本包首次全流程实测（下载 → 安装 → 使用）随发布进行，结果将回填本节。
同协议族的 `knowledge-growth` 运行时矩阵可作参考，但不等于本包实测。
其他 Agent 不作默认承诺。

## 安装

### 方式一：独立使用（不需要 knowledge-growth）

```bash
git clone https://github.com/bernardw5174-zfyb/job-search-bw.git
```

用兼容 Agent 打开这个目录即可。

### 方式二：作为 knowledge-growth 垂直包（推荐）

```bash
cd vault/ && mkdir -p _packages
git clone https://github.com/bernardw5174-zfyb/job-search-bw.git _packages/job-search-bw
```

然后在 Agent 里说"我要开始求职"，让它建你的私有工作区 `vault/求职/`。

**包只读、你的数据在 `vault/求职/`——升级 pull 包，永远不影响你的资料。**

### 方式三：不会 git（ZIP）

GitHub Release 下载 zip → 解压 → 放入 `vault/_packages/job-search-bw/`。
⚠️ 代价：无法 `git pull`，包内后续更新（含验证状态推进）需手动重下覆盖。

## 来源与适配

`02-框架/` 每份文档含「来源与适配说明」节——出处、本地适配、适用边界。

## 项目状态与维护承诺

- 单人维护；不定期更新；欢迎 fork 接手
- 资料为纯 Markdown＋YAML，项目停更后仍可被任意 Agent 读写（数据逃生）
- 假设注册表有**停滞标注规则**：连续 60 天无新证据会明示，不装还在推进
- 验证节奏：每完成一轮投递（≥5 个岗位）更新一次状态与证据

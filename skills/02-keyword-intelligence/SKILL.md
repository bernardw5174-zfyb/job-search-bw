# 关键词情报

对标 JD 文本与简历，输出关键词行动清单。**本 skill 只走流程，分类与判定规则见框架文档。**

## 触发条件

- 用户说"看下这个 JD 匹配吗 / 我的简历有没有说 JD 的语言 / 关键词怎么补"
- 准备投新方向，不确定简历用什么词

## 前置检查

- 读 `02-框架/关键词情报框架-国内版.md`（关键词四分类、两轮筛选匹配度、封顶规则）
- **首次使用判断**：`00-raw/` 无 JD 语料且本次对话无 ≥10 份 JD → 提示"首次使用建议先做岗位词频校准"（选项：a) 现在校准——收集 10-15 份目标 JD；b) 用现有语料直接对标——结果近似并标注；c) 用 `03-实战/示例/` 练习）
- 确认**场景**（语料门槛不同）：
  - **建词表／方向对标**（找岗位语言、补缺失词）→ 需 **10-15 份**同类岗位 JD 语料（框架第 1 步要求；不足则提示"先收集，或用现有语料做近似对标并标注")
  - **单 JD 评估**（这个 JD 匹配吗）→ 1 份 JD 即可（走硬性分层/覆盖率/证据矩阵）

## 流程步骤

**场景 A · 建词表／方向对标**（找岗位语言、补缺失词）：

1. 确认语料：≥10-15 份同类岗位 JD（不足时不虚构词表——提示补齐或用现有语料做近似对标并标注）
2. **语料健康度检查**：英文主体 → 单独英文词表；逐字重复 → 去重标注；<10 份 → 标"近似词表"；语境歧义词 → 按语境拆；混合跑 → 提示按岗位族分组（#5，分组从语料中识别不预置）
3. 频率分析：提取高频词，按四分类标注（行业/职能/工具/AI 趋势）
4. 对标简历：逐词标 缺失/埋没/过时
5. 输出行动清单：先保 table-stakes → 前置埋没词 → 加趋势词 → 删废话词
6. 提示平台双轨：改词同时打到在线简历与附件 PDF
- 产出：词表确认后落 `01-知识/`（对标基准）

**场景 B · 单 JD 评估**（这个 JD 匹配吗）——**关卡递进：不通过就停，不浪费下一级成本**：

**第 0 级 · 幽灵岗预检**（**最先，每次看 JD 先过**，≤1 分钟）：
- 岗位真实性信号：挂载时长异常／同岗位重复出现／招聘内容雷同／公司业务与岗位对不上／渠道无响应迹象
- → 幽灵岗信号 → **直接否决，不跑任何评估**（投递价值归零，人岗匹配再高也没意义）
- 检测细节见 `02-框架/企业甄别清单-国内版.md`「幽灵岗检测」

**第 1 级 · 快速筛**（**L0 通过后必跑**，≤5 分钟）：
- a. 硬性分层 A/B/C（A/B 一票否决——JD 原文＋客观事实判定）
- b. 语言提醒（英语门槛——提醒不裁决）
- c. 五维评分（宏观快速直觉：技能/经验/文化/地点/职业）
- → 输出一句话："否决（停止，不跑深度）／存疑／值得投"

**第 2 级 · 深度评估**（**仅 L1 未否决时**——存疑/值得投才跑，30-60 分钟）：
- d. 系统层覆盖率（关键词计算，低于漏推线先改文本层）
- e. 人工层证据矩阵（要求×证据×得分）
- f. 封顶规则＋overqualified 检查
- → 输出：结论卡＋证据附录（报告分层见下）

**第 3 级 · 公司核检＋投递登记**（**仅 L2 结论"可投"时**，15 分钟）：
- g. 公司核检（五渠道核查：公司状态／近期动态／评价——读 `02-框架/企业甄别清单-国内版.md`；Agent 提供清单不代查，判断归用户）
- h. 投递登记（投递动作前先登记：查重后写入 `00-raw/投递记录/`）

**规则**：L0 幽灵岗预检否决的**不跑任何评估**（投递价值归零）；L1 否决的**不跑 L2**（成本匹配决策）；L2 "暂不建议"的**不跑 L3**（先改文本层，还没到投递阶段）。每级产出喂给下一级，不跳级。

## 输出规范（报告分层）

单 JD 评估／诊断结果**分两层输出**：

**第 1 层 · 结论卡**（首屏，30 秒可读）：
- 一句话结论（投／不投／改什么）
- 3 个关键数字（如：系统层覆盖率／人工层得分／最近 3 年篇幅）
- Top 3 修复（按影响力排序的 before → after）
- 待确认问题清单（≤7 项，标注"不代写"）

**第 2 层 · 证据附录**（用户要求展开时）：
- 完整矩阵（要求×证据×得分）、逐段诊断、数字复算
- 每条可回指（来源标注），验证机制保留

规则：**首屏不写证据推理，附录不省略数字依据**——决策效率在结论卡，验证机制在附录，两层都要。
- **过程静默**：评估的中间步骤（复读 JD 原文／跑脚本／核验关键词表／修 bug／重跑）**静默执行，不进入回复**——回复只含结论卡＋（用户要求时的）证据附录；过程细节（工具调用、调试、重跑）只有用户明确要求"调试记录/中间过程"时才展开。用户问的是决策，不是你的工作日志。
- **复算合并与预告**（配合过程静默）：所有复算**合并为一次批处理命令**（一次批准跑完全部计算——词频、覆盖率、矩阵，不逐条执行）；执行前**一句话预告**："我要运行复算脚本确认数字（只计算、不写文件），批准即可"——把"为什么需要批准"说清楚，不让用户面对裸的"执行命令？"弹窗。
- **状态进度提示**（配合过程静默）：过程静默隐藏的是**技术细节**，不是状态——执行前预告"要做什么、约多久"；长任务（>1 分钟）给**粗粒度阶段提示**（如"复算完成，正在核验关键词表…"）；**不显示**工具调用/bug/重跑等细节。纯读秒等待是错的（用户不知道卡没卡），有信息的等待才是对用户负责。

## 产出位置

- 对话输出（关键词报告 / 单 JD 评估）
- **单 JD 评估结论**：即时决策产物，**默认对话输出、不落盘、不问去向**——需要记录的（如决定投递的 JD）由用户显式说"帮我记住/登记"
- **建词表场景**：词表确认后写用户工作区 `01-知识/`（独立使用）或 `vault/求职/01-知识/`（Core 挂载）——作为对标基准；重算时旧词表标 `superseded_by`，不删历史
- 不自动写文件；用户要求时写用户工作区 `01-知识/_drafts/`

## 边界

- 不虚构关键词库——必须基于用户提供的真实 JD 文本
- 语言要求只提醒、不替用户砍岗（"流利英语"类由用户拍板）
- overqualified 信号只警示、不一票否决

# 材料接收（微信文章 / URL / 附件）

处理用户丢来的求职相关材料（最常见：微信公众号文章、招聘链接、简历附件）。**本 skill 只走流程，边界见根 `AGENTS.md`「材料与链接处理」节。**

## 触发条件

- 用户丢来微信文章 URL / 网页链接 / 附件（JD、招聘信息、简历、方法论文章等）
- 用户说"看看这篇文章 / 这个招聘 / 这份材料"

## 前置检查

- 读根 `AGENTS.md`「材料与链接处理」节（处理流程与版权/隐私边界）
- 判断材料类型：招聘信息（JD）／方法论文章／行业资讯／个人材料（简历等）

## 流程步骤

1. **先处理，不追问**：读取 / 抓取正文，给出「讲了什么 ＋ 与求职的关系 ＋ 不确定项」
2. **用选项问去向**：存进知识库 / 不用存 / 提炼框架候选 / 其他
3. **若存**：确认领域（默认求职）→ 落 `00-raw/`（网页抓取标「非字节级 ＋ 时间戳 ＋ URL」）→ `01-知识/_drafts/` 生成草稿（**停在草稿等确认**，不自动晋升）
   - **JD 发布时间采集（L0 幽灵岗输入）**：材料为 JD／招聘信息时，**若页面含 JD 发布时间／挂载时长／招聘期限信息，一并记录到 Raw 文件头**（如 `published: 2026-08-15`）——L0 幽灵岗检测的第一信号"挂载时长异常"依赖此输入；页面无则不编造，标"unknown"
4. **类型引导**：
   - **JD／招聘信息** → 提示走 `skills/02-keyword-intelligence`（关键词对标／单 JD 评估）；**积累 10-15 份同类 JD 可建岗位词表**（框架第 1-2 步语料驱动，词表随语料重算）
     - **累积提示**：入库后数 `00-raw/` 文件数 N（近似 JD 数）；**N ≥ 10 且 N 为 10 的倍数**时提示："语料已累积约 N 份，是否重跑词表？（喂 `00-raw/` 全部 JD 走频率分析）"——近期已提示过则忽略
   - **方法论文章** → 草稿标注来源与版权边界；可提示"是否提炼框架候选"（须先入库确认）
   - **行业资讯** → 草稿为主，价值判断归用户
5. **版权与隐私**：内容仅存私有工作区，不 push；公开仓库零写入

## 产出位置

- 对话输出（处理结果 ＋ 去向选项）
- 用户确认后：`00-raw/`（材料）＋ `01-知识/_drafts/`（草稿）

## 边界

- 微信/网页抓取一律标「非字节级」，不得冒充原始文件
- 不自动晋升草稿（判断归人）
- 外部文章不编译进 `02-框架/` 或公开内容（版权）
- 不替用户决定"这篇值不值得留"
